# Игра в пары

Игра на запоминание: нужно переворачивать карточки и находить среди них пары. На всё даётся 30 секунд. Перед началом игры выбирается количество пар — чётное число от 2 до 10, по умолчанию 4. Победа — все пары найдены до окончания времени.

## Запуск

Проект использует нативные ES-модули, поэтому страницу нужно открывать через локальный статический сервер (прямой запуск из файловой системы не сработает из-за CORS):

```bash
python -m http.server 8000
# или
npx serve .
```

Затем открыть `http://localhost:8000`.

Сборка и зависимости не нужны: достаточно браузера с поддержкой ES-модулей и приватных полей классов.

    GameStatus.js       перечисление состояний партии
    CardCatalog.js      доступные типы карт
  application/          сценарии использования и порты

    FinishGame.js       завершение по таймауту

## Архитектура

Применена чистая архитектура: зависимости направлены внутрь, от внешних слоёв к домену.

- **Domain** — чистая игровая логика. Не знает ни о DOM, ни о таймере браузера.
- **Application** — use cases оркестрируют домен и общаются с внешним миром только через порты `Timer` и `GameOutput`.
- **Interfaces** — конкретные реализации портов: DOM-представления, presenter, контроллер и браузерный таймер.
- **Composition root** (`js/main.js`) — единственное место, где создаются и связываются все объекты.

Дополнительно используются: инверсия зависимостей, presenter + ViewModel, инкапсуляция через приватные поля классов, делегирование событий на контейнере игрового поля.

## Анимации

Переворот карты делается средствами CSS 3D: `.card` содержит две стороны (`.card__face--shirt` и `.card__face--value`), а класс `is-flipped` поворачивает внутренний контейнер на 180°. `BoardView` переиспользует уже созданные DOM-элементы и меняет только классы, поэтому анимация не сбрасывается при каждом ходе. Совпавшие пары получают класс `is-matched` с короткой подсветкой. При системной настройке `prefers-reduced-motion` анимации отключаются.

## Разработка

Ветвление по Git Flow: `main` — релизы, `develop` — интеграция, `feature/*` — новые возможности, `release/*` — подготовка релиза, `hotfix/*` — срочные исправления. Коммиты оформляются по конвенции Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:` и др.).

Проверка синтаксиса модулей без установки зависимостей:

```bash
for f in $(find js -name '*.js'); do node --input-type=module --check < "$f"; done
```
